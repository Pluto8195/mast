## P1 — confusing or misleading

1. **A configured PR-merged wake cannot fire.** `note_pr_merged` constructs the event (`crates/engine/src/orchestrator_wakes.rs:453`), but a repository-wide Rust search finds only that declaration; the default is off (`crates/engine/src/orchestrator_wakes/core.rs:400`). Turning it on creates an expectation that a merge will reach the coordinator, but there is no producer. Wire the PR state transition to this method with deduplication, or remove the control until it works. **M.**
2. **Worker reports and held wakes are volatile.** The held queue and delivered keys are in-memory vectors/maps (`crates/engine/src/orchestrator_wakes/core.rs:95`); report delivery is queued through that same core (`crates/engine/src/orchestrator_wakes.rs:529`). A restart while a user draft or active turn holds a report can lose the worker's final result; other-device parents are explicitly refused (`crates/engine/src/orchestrator_wakes.rs:514`). Persist pending events and dedupe identities, and surface undelivered reports. **L.**
3. **MCP descriptions contradict reach and archive behavior.** `create_chat` describes project-wide item reach but its `workItemId` parameter says only own item/descendants (`crates/mcp/src/tools.rs:140`, `:145`); `work_outline_create_child` similarly disagrees with its parent parameter (`:273`, `:279`). `archive_chat` says all non-archivable chats require force (`:224`), while direct children and non-child admin targets bypass that check (`crates/engine/src/agent_tools/archive.rs:169`). Agents can unnecessarily refuse valid work or assume an archive safeguard applies. Generate descriptions from a shared reach/permission contract and cover examples for ordinary, project and admin callers. **S–M.**
4. **Diff target limit gives an unavailable remedy.** The engine tells users to unbind a checkout in the Changes picker at the limit (`crates/engine/src/diff_targets.rs:299`); it implements `unbind` (`:349`), but searches of the Changes UI find no unbind action. Existing paths that remain on disk can occupy all slots, blocking new targets. Add removal in the picker and test the limit-to-recovery path. **M.**
5. **PR dashboard silently scores only the first 100 files.** The GraphQL query requests file page metadata (`crates/engine/src/pr_dash.rs:86`), but the implementation explicitly sees only the first 100 files (`:675`, `:856`). Large PRs can show misleading churn and buckets without a completeness indicator. Page files or mark metrics partial. **M.**
6. **Two template systems use the same word for different change semantics.** Saved project templates copy a tree and later edits do not change the template (`crates/ui/src/work_outline/details_templates.rs:229`, `:247`); container templates define live rules, and moved-in children need Apply (`crates/ui/src/work_outline/details_container_template.rs:1`, `:11`). A coworker can choose the wrong system and expect edits to propagate. Make the distinction explicit at creation and offer a migration path. **M–L.**
7. **Long render comparisons omit content.** Highlight/onion snapshots cap height at 16,000 CSS pixels and 20 million pixels (`crates/ui/src/artifacts/document.rs:104`); coverage is reported (`:130`), so this is not the older handoff's silent cutoff. Changes below the cap are absent from the visual result. Tile snapshots or make the limitation prominent before reviewers rely on it. **L.**

## P2 — polish and narrower gaps

8. **Plan comparison zoom differs by mode.** The comparison explicitly mirrors zoom between web frames, not the single-picture onion mode (`crates/ui/src/artifacts/tab/compare_view.rs:211`); users switching modes lose the expected magnification. Support zoom for the image stack. **M.**
9. **Terminology: Space and project refer to overlapping but distinct things.** README calls a Space a project folder and separately describes per-project accounts (`README.md:16`, `:23`); the MCP calls a folder on a device a project (`crates/mcp/src/tools.rs:98`), while outline project scope is a marked ancestor (`:140`). Agents and people can confuse filesystem Space with an outline project. Adopt a single glossary and label both scopes where they meet. **M.**
10. **Linux browser evaluation is incomplete.** Linux paths explicitly lack general and result-returning evaluate (`crates/ui/src/browser/mod.rs:266`, `:286`). Features depending on script evaluation can behave differently there. Clarify platform support or implement the missing bridge. **M–L.**
11. **Real integration confidence is limited.** HANDOFF records Linear project/attachment queries as unverified (`docs/plans/work-outline/HANDOFF.md:782`); ignored PR tests require authenticated `gh` and network (`crates/engine/src/pr_ticket_cache.rs:1720`, `:1972`). This is a verification gap, not proof of broken behavior. Run a separately authorized manual sandbox-account smoke test; keep network out of automated tests. **M.**

## Consolidation proposals

- Use one attention model for Required Actions, plan questions and worker reports: a durable event with provenance, delivery state and a link to the owning question/chat; keep plan cards as a presentation of that record. Wakes should notify about the record rather than be the only copy.
- Give copied project templates and live container rules distinct labels and one discoverable entry point. Explain propagation and provide a previewed conversion instead of making users reconstruct trees.
- Define a shared chat-status and archive policy model used by sidebar, Outline, Team, running popover and menu bar, with role-specific archive permissions stated separately. Expose the same reason everywhere.
- Make PR identity and status a shared view model for the PR page, outline, item and chat strip; mark partial/stale data and link each surface to the canonical review workflow.
- Publish a scope matrix for Space, outline project, subtree, direct child and temporary admin grants; derive UI help and MCP descriptions from it.

This does not establish usage: aliases, macros, build scripts, dev/target dependencies and transitive feature unification require `cargo machete`/`udeps` and manual review later. No dependency is recommended for deletion on this evidence.
- **Ignored tests:** authenticated/network cases at `crates/engine/src/pr_ticket_cache.rs:1710`, `:1723`, `:1972`, a private snapshot (`crates/engine/src/chat_persistence.rs:194`), and benchmarks (`crates/ui/src/perf/mod.rs:1`) are intentionally gated, not necessarily dead fixtures. - **Existing cleanup proposal:** the separate repo-cleanup proposal (HANDOFF `docs/plans/work-outline/HANDOFF.md:749`) already covers docs relocation, upstream apps/scripts/workflows, `.gitignore`, and a secrets sweep; do not duplicate it here.
